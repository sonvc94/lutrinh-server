## Package

- A version of a route = `route.json` + media files named by their lower-case hex sha256
  (`media/<sha256>.jpg|.mp4` in the optional `.lutrinh-route.zip`). No absolute URLs inside.
- `route.json` bytes are canonical JSON (RFC 8785 / JCS): UTF-8, no whitespace, keys sorted by
  UTF-16 code units, numbers as ECMAScript prints doubles (`5.0` → `5`, `1e21` → `1e+21`),
  only `"` `\` and U+0000–U+001F escaped. Read numbers as IEEE-754 doubles. The sha256 of these
  bytes is the package hash (HTTP ETag, `route_links.package_sha256` in the app).
- `formatVersion` greater than 1 → `format_unsupported` before any other check (the app says
  "Hãy cập nhật ứng dụng"). Readers of formatVersion 1 should ignore keys they do not know; the
  server never writes keys outside the schema.
- Text fields are trimmed; lengths are counted in code points (route title 1..60, description
  ≤ 1000, stop title 1..80, note ≤ 2000, as the app's docs/02).
- Stops: 2..200, `day` 1..30, `time` `HH:mm` or null (app: 08:00 + position in minutes),
  `arrival` = app TransportMode code or null, ≤ 30 media per stop.
- `arrivalNote` (optional, added within formatVersion 1): a note on the travel from the previous
  stop to this one, next to `arrival` ("Đường dốc khó đi", "Gửi xe phía đối diện, 30k"); trimmed,
  1..1000 code points, absent (never `""` or null) when there is none. It belongs to the stop,
  not to `legs[]`, so it also exists for train/plane/boat arrivals and survives leg recompute.
  Never on the first stop: the server blocks publishing (`arrival_note_first_stop`, a publish
  rule, not an integrity rule) and so never writes one there. Readers that predate the field and
  reject unknown keys (the app's strict reader) refuse packages carrying it.
- Legs: optional, one per stop at most, keyed by the arrival stop `to`; `path` is polyline6
  (empty unless `status` is `ok`); `source` is a router id (`valhalla`, `osrm`), `manual` (drawn
  in the admin) or `gpx` (cut from an imported track).
- `region.bounds` = box around every stop and every `ok` leg path; `readyMade` = the app's R15
  region key or null.

## Decisions on route.json fields (Mate, during server-foundation)

Mate's answer, verbatim: "1A 2A 3A — size.files counts media files only; no poster frames in
the package (app makes its own); media.credit required non-empty on every item, matching page
04's publish blocker (the admin UI may prefill it later)."

Our reading: `size.files` = length of `media[]` (route.json is not counted; `size.media` = sum
of `media[].bytes`); video thumbnails are never package files; `media[].credit` is a required,
trimmed, non-empty string on photos and videos alike.

## Integrity rules (after the schema passes)

Problem codes, as reported by `lutrinh.core.package.check` and expected by `package-vectors.json`:

| Code | When |
| --- | --- |
| `duplicate_stop_id` / `duplicate_media_id` | an id appears twice |
| `day_after_end` | a stop's `day` > `route.days` |
| `unknown_media` | a stop's media id or `route.cover` is not in `media[]` |
| `cover_not_photo` | `route.cover` is a video |
| `orphan_media` | a `media[]` item is used by no stop and is not the cover |
| `unknown_stop` | a leg's `to` is not a stop id |
| `leg_to_first_stop` | a leg ends at the first stop (no previous stop) |
| `duplicate_leg` | two legs end at the same stop |
| `leg_order` | legs are not in stop order |
| `bad_path` | `path` is not valid polyline6 |
| `size_mismatch` | `size.media` / `size.files` do not match `media[]` |

Schema failures are reported as `schema`; integrity rules run only on schema-valid documents.
Publish-time rules live in `server/lutrinh/core/rules.py` (not in the vectors): days and times
ascending within a day, no `arrivalNote` on the first stop, package ≤ 300 MB, `route.json`
≤ 2 MB block publishing; warnings for a large package, missing/failed/car-fallback/long legs.

## Codes

8 characters shown `XXXX-XXXX`, alphabet `23456789ABCDEFGHJKMNPQRSTVWXYZ` (30), value = index.
Normalise: upper-case ASCII a–z; remove space, tab, CR, LF, `-`; nothing else is rewritten.
Then: length ≠ 8 → `bad_format`/`length`; first character outside the alphabet →
`bad_format`/`confusable` if it is one of `O 0 I 1 L U`, else `bad_format`/`char`; the 8th
character must be the Luhn mod 30 check of the first 7 (rightmost payload character doubled,
doubled values folded as `v // 30 + v % 30`) → else `bad_check`. Every single substitution is
caught; a few adjacent swaps are not (`2`↔`Z`, see `adjacentTranspositions`).

## Public API `/api/v1` (server ↔ app)

Page 03 of the design, as built in `server/lutrinh/api/public.py` (tests: `server/tests/public/`).
JSON; errors are `{"error": {"code", "retryAfterS", "detail"?}}` with the codes of page 03
("Bảng lỗi"), `Retry-After` on 429.

| Request | Answer |
| --- | --- |
| `GET /api/v1/codes/{code}` | summary: `code` (`XXXX-XXXX`), `routeId`, `version`, `formatVersion`, `title`, `description`, `days`, `stops`, `distanceM` (sum of leg `distanceM`), `photos`, `videos`, `bytes` = `size.media`, `files` = `size.files`, `region`, `overview` (polyline6, ok-leg paths else stop points, Douglas-Peucker ~200 m), `cover` (`/api/v1/dl/<token>/media/<sha>?w=640` or null), `downloadToken` (`tk_…`), `tokenExpiresAt` (2 h) |
| `GET /api/v1/dl/{token}/route` | the previewed version's `route.json` bytes, `ETag: "<sha256>"` (`If-None-Match` → 304), `Content-Type: application/vnd.lutrinh.route+json;v=1` |
| `GET /api/v1/dl/{token}/media/{sha256}` | one file of that version; `Range` → 206; `Cache-Control: public, max-age=31536000, immutable`; `?w=640` → the 640 px preview when the server has one, else the full photo |
| `POST /api/v1/updates` | body `[{code, routeId, version}]` (≤ 50, else 400 `too_many`) → `{"results": [{code, routeId, status, …}]}` in request order, `code` echoed as sent; `status` `current` (+`version`) \| `newer` (+`version`, `publishedAt`, `note`, `changes: {stopsAdded: [ids], stopsRemoved: [ids], stopsEdited: n, mediaAdded: n, bytes: n}`, bytes = media not in the app's version) \| `unpublished` \| `revoked` \| `expired` |
| `GET /api/v1/meta` | `{"formatVersions": [1], "minAppVersion": {"android", "ios"}, "maintenance": bool, "message": str\|null}` |

### Decisions (Mate, during server-public-api)

Mate's answer, verbatim: "accept every recommendation in /tmp/server-public-api-decisions.md: 1B
(ffmpeg-generated placeholder JPEG/MP4, normal publish, spec/ unchanged), 2–9 as written."

Our reading of the accepted recommendations:

1. `lutrinh seed-sample` turns this sample's text, stops and legs into a new route, generates
   placeholder media with ffmpeg and publishes it normally: its `route.json` has its own hashes
   and sizes (the sample's media hashes are of placeholder strings). This directory is unchanged.
2. A failed lookup is a 400 (`bad_format`/`bad_check`) or 404; a 410 counts only as a lookup.
   30 lookups / sliding hour / IP → 429 until the oldest leaves the hour. The 10th failure in an
   hour locks the IP (every lookup 429): 1 h, then 4 h, then 24 h; the ladder resets after 24 h
   without a lock. 500 failures / hour system-wide → mail + 3 failures / hour / IP for 24 h.
3. Tokens: `tk_` + 32 random bytes (urlsafe), stored in SQLite. Unknown or expired → 401
   `token_expired`; the code revoked/expired or the route unpublished/trashed since → that 410;
   a sha256 not in the token's version → 404 `not_found`.
4. `route.json` 10 / hour / code / IP; media requests per token ≤ files × 3 (cover included);
   monthly bandwidth = bytes the API hands out (whole file or the Range length), cap 100 GB by
   default, mail at 70 %, 503 `quota` at the cap. All counters in SQLite.
5. Maintenance is a setting for now (`LUTRINH_MAINTENANCE`, `LUTRINH_MAINTENANCE_MESSAGE`);
   `/meta` stays 200 and says so, every other `/api/v1` route answers 503 `maintenance`.
6. Shapes as in the table above (they match the app's `LuTrinhServerCatalog`); an unknown or
   malformed code, or a `routeId` that does not match the code, → `unpublished`. `/updates` has
   no rate limit beyond ≤ 50 links.
7. `Accept: application/vnd.lutrinh.route+json;v=N` with N below the package's `formatVersion` →
   406 `format_unsupported` on `/codes` and `/dl/…/route`; no such Accept → served.
8. Files on disk: `media/ab/cd/<sha256>.jpg|.mp4`, preview `<sha256>.w640.jpg`. With
   `LUTRINH_MEDIA_ACCEL=true` the API answers `X-Accel-Redirect: /ab/cd/<sha256>.<ext>` (relative
   to `media/`, page 06 Caddyfile); otherwise it sends the file (Range included).
9. IP rows older than 14 days are deleted by the API as it writes and nightly by the worker (`purge.iplog`);
   `daily_counts` kinds: `lookup`, `bad_lookup`, `download` (= `route.json` served).
