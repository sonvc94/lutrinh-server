# spec/ — shared rules for the server (Python) and the app (Kotlin)

Data only; no code the app must run. Both sides load these files in their tests (design D-23 A).
The app copies `spec/` with a script that checks sha256s (app task, not here).

| File | What |
| --- | --- |
| `route.schema.json` | JSON Schema 2020-12 of `route.json`, `format: "lutrinh-route"`, `formatVersion: 1` |
| `samples/ha-giang-4n/route.json` | Sample package, 9 stops / 4 days / 8 legs / 12 photos + 2 videos, stored as canonical bytes |
| `samples/ha-giang-4n/expected.json` | Its sha256, byte length and counts |
| `package-vectors.json` | Mutations of the sample (RFC 6902 add/remove/replace) and the problem codes a reader must report |
| `codes.json` | Route code vectors: valid inputs, invalid inputs with error + reason, every single-character typo of each sample, adjacent transpositions |
| `canonical-json.json` | Canonical JSON (RFC 8785) input → exact output |
| `tools/gen_codes.py` | Standalone generator of `codes.json` (independent Luhn implementation; `python3 spec/tools/gen_codes.py`) |

The sample is regenerated by `server/scripts/make_spec_sample.py`. Changing any file here is a
spec change: the app's copy and tests must follow.

## Package

- A version of a route = `route.json` + media files named by their lower-case hex sha256
  (`media/<sha256>.jpg|.mp4` in the optional `.lutrinh-route.zip`). No absolute URLs inside.
- `route.json` bytes are canonical JSON (RFC 8785 / JCS): UTF-8, no whitespace, keys sorted by
  UTF-16 code units, numbers as ECMAScript prints doubles (`5.0` → `5`, `1e21` → `1e+21`),
  only `"` `\` and U+0000–U+001F escaped. Read numbers as IEEE-754 doubles. The sha256 of these
  bytes is the package hash (HTTP ETag, `route_links.package_sha256` in the app).
- `formatVersion` greater than 1 → `format_unsupported` before any other check (the app says
  "Hãy cập nhật ứng dụng"). Readers of formatVersion 1 should ignore keys they do not know; the
  server never writes keys outside the schema.
- Text fields are trimmed; lengths are counted in code points (route title 1..60, description
  ≤ 1000, stop title 1..80, note ≤ 2000, as the app's docs/02).
- Stops: 2..200, `day` 1..30, `time` `HH:mm` or null (app: 08:00 + position in minutes),
  `arrival` = app TransportMode code or null, ≤ 30 media per stop.
- Legs: optional, one per stop at most, keyed by the arrival stop `to`; `path` is polyline6
  (empty unless `status` is `ok`); `source` is a router id (`valhalla`, `osrm`), `manual` (drawn
  in the admin) or `gpx` (cut from an imported track).
- `region.bounds` = box around every stop and every `ok` leg path; `readyMade` = the app's R15
  region key or null.

## Decisions on route.json fields (Mate, during server-foundation)

Mate's answer, verbatim: "1A 2A 3A — size.files counts media files only; no poster frames in
the package (app makes its own); media.credit required non-empty on every item, matching page
04's publish blocker (the admin UI may prefill it later)."

Our reading: `size.files` = length of `media[]` (route.json is not counted; `size.media` = sum
of `media[].bytes`); video thumbnails are never package files; `media[].credit` is a required,
trimmed, non-empty string on photos and videos alike.

## Integrity rules (after the schema passes)

Problem codes, as reported by `lutrinh.core.package.check` and expected by `package-vectors.json`:

| Code | When |
| --- | --- |
| `duplicate_stop_id` / `duplicate_media_id` | an id appears twice |
| `day_after_end` | a stop's `day` > `route.days` |
| `unknown_media` | a stop's media id or `route.cover` is not in `media[]` |
| `cover_not_photo` | `route.cover` is a video |
| `orphan_media` | a `media[]` item is used by no stop and is not the cover |
| `unknown_stop` | a leg's `to` is not a stop id |
| `leg_to_first_stop` | a leg ends at the first stop (no previous stop) |
| `duplicate_leg` | two legs end at the same stop |
| `leg_order` | legs are not in stop order |
| `bad_path` | `path` is not valid polyline6 |
| `size_mismatch` | `size.media` / `size.files` do not match `media[]` |

Schema failures are reported as `schema`; integrity rules run only on schema-valid documents.
Not here yet (later `core/rules.py`): times ascending within a day, package ≤ 300 MB,
`route.json` ≤ 2 MB, publish warnings.

## Codes

8 characters shown `XXXX-XXXX`, alphabet `23456789ABCDEFGHJKMNPQRSTVWXYZ` (30), value = index.
Normalise: upper-case ASCII a–z; remove space, tab, CR, LF, `-`; nothing else is rewritten.
Then: length ≠ 8 → `bad_format`/`length`; first character outside the alphabet →
`bad_format`/`confusable` if it is one of `O 0 I 1 L U`, else `bad_format`/`char`; the 8th
character must be the Luhn mod 30 check of the first 7 (rightmost payload character doubled,
doubled values folded as `v // 30 + v % 30`) → else `bad_check`. Every single substitution is
caught; a few adjacent swaps are not (`2`↔`Z`, see `adjacentTranspositions`).
